# 任务耗时显示设计

## 用户需求

网页对话内嵌真实 TUI。现有会话时钟包含闲置时间，容易被误解为任务耗时；本轮计时在回复结束后消失，后台接续还会重新开始计时。

## 显示与口径

- 一条真实用户需求建立任务计时，后台进程通知、委派结果、自动续跑沿用起点。
- 从需求提交到最终回复计时，包含后台等待；完成、报错或中断后冻结。
- 底部独立一行展示本次任务时间，避免长标题挤占；最终回复下方保留耗时。
- 图形聊天页在标题栏持续显示当前任务时间，已完成回复下方保留冻结耗时；切换会话和刷新后按各自会话恢复。
- 现有会话时钟明确标记为“会话时长（含闲置）”。
- 历史记录通过持久化展示元数据恢复；旧记录以真实用户消息到最后回复的时间差估算并标“约”。缺失或倒退的时间戳不推测。

## 实现边界

计时逻辑放在独立的 TUI 网关模块，复用既有消息时间戳、用户来源识别、后台任务注册表和展示元数据。只扩展已有开始、完成和会话信息协议，不添加模型工具、不修改模型消息正文或系统提示。前端负责计时格式和展示，不决定后台任务生命周期。

多个用户需求分开计时；任务内的后台接续共用起点。历史估算不是模型运算时间，旧记录无法证明完整生命周期时保留估算标记。
