# 网页聊天文件粘贴设计

## 目标

在 Dashboard 的 `/chat` 中，用户可以粘贴、拖入或选择 PDF 等普通文件。浏览器拿到文件字节后，以流式请求传到当前 Hermes profile 的 `attachments/`，再把 `@file:` 引用插入真正的 TUI 输入框。用户检查文字后自行发送；不另建一套网页聊天输入框。

图片沿用现有上传和 `/image` 附件流程。纯文字粘贴沿用终端流程。浏览器只提供文件名而不提供文件字节时，无法据此读取用户电脑上的文件；页面提供选文件入口兜底。

## 接口与边界

- 增加经过 Dashboard 现有认证保护的 `POST /api/chat/file-upload`，使用 multipart 流式上传和既有文件大小上限。
- 服务端生成唯一文件名，清理目录分隔符和控制字符；写入由 `profile` 选定的 `HERMES_HOME/attachments/`。目录已经纳入终端后端的挂载与同步规则。
- 返回绝对路径与原始显示文件名。前端插入符合 `@file:` 语法的引用；PDF 作为磁盘文件交给现有上下文引用和工具处理。
- 粘贴与拖入只拦截确实含文件的事件；Ctrl/⌘V 跳过 xterm 的按键翻译，由浏览器发出原生 `paste` 事件，以保留文件对象和文件名。纯文字继续由 xterm 的粘贴监听器处理。
- 上传失败明确告知用户，不向输入框插入失效引用。

## 验证

用后端真实路由测试认证、profile 隔离、文件内容和超限清理；用网页测试文件提取、粘贴/拖入到输入框的引用及图片/文字回归，并运行类型检查和相关测试。
